# Lote FX05 (front): correcciones de la verificación final

Contexto: los 39 puntos del review de Catálogos E2 (docs/reviews/2026-10-23-code-review-catalogos-e2.md del back) ya están implementados. Tres verificaciones de solo lectura y las revisiones finales de cada lote dejaron los hallazgos de abajo. Este lote corrige los de su área. El pedido del usuario de cada punto está en los briefs Fxx.md y Bxx.md de esta carpeta (F49.md trae 35 a 39). Las reglas de interfaz están en docs/design/visual-baseline.md del front («Pantalla» y «Formularios y diálogos») y el contrato de mensajes en docs/guides/mensajes-y-estados.md.

Cómo trabajar cada hallazgo: verificalo primero en el código actual (pudo cambiar después de que se escribió). Si no es real, no cambies nada y explicalo. Si es real, regresión en rojo primero cuando es comportamiento, después el arreglo, y un commit chico por hallazgo o por grupo de hallazgos repetidos. Si un hallazgo cambia lo que muestra una prueba visual (src/test/visual), actualizá su spec; las capturas se regeneran al cierre. Si cambia una regla o una guía, actualizala en el mismo commit.

### Pendiente de la revisión final del lote F49 (blocker)

Dónde: C:\Users\ezequ\source\repos\ArquitecturaBaseFront\src\features\business-forms\pages\FormEditorPage.tsx:352 (DraftReview onCloseAutoFocus), together with the new saveEnabled at :193/:296

Problema: The fix breaks focus return after the draft review, which used to work. Steps: on a saved form, a save gets a 409, the person presses «Revisar», then «Usar borrador actual». `editor.useCurrent` calls `openDraftSession(review.definition)`, so value equals baseline, `dirty` is false and `confirmed` is set. With the new `saveEnabled = editor.canSave && (dirty || !session?.confirmed)`, «Guardar borrador» is now disabled. The dialog's onCloseAutoFocus calls `preventDefault()` and then tries `reviewReturnFocus`. That target is the «Revisar» button of the «Revisión del borrador» surface, which unmounted when the phase went back to Editing. The code then falls back to `(saveButton.current ?? …)?.focus()`. `saveButton.current` is not null but the button is disabled, so `.focus()` does nothing and focus ends up on `body`. Before the fix, canSave was true in Editing, so Save was enabled there and received focus. The same happens with «Conservar mis cambios» when the resolution keeps nothing different from the current revision. No unit or visual test clicks «Usar borrador actual» in the editor (no test file has «Usar borrador actual»/«Use current draft»), so the 47/47 run and the visual specs cannot see this.

Arreglo propuesto: In DraftReview's onCloseAutoFocus, pick the first connected, enabled target, the same way PublicationCheckDialog does: `[reviewReturnFocus.current, saveButton.current, host.current?.querySelector('[data-form-text="name"]')].find(n => n?.isConnected && !n.matches(':disabled'))?.focus()`. Add a regression in FormsPage.test.tsx using the forms-conflict scenario: Save → 409 → Revisar → «Usar borrador actual». It should check that «Guardar borrador» is disabled and that focus is on a usable control (not body). Write it red first.
