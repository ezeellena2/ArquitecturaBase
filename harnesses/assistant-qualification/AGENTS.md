# Assistant qualification harness

Development-only console outside the solution. Manual invocation; default/--list must not load secrets, DI, databases or a provider. --live is explicit and uses an isolated fictitious database and the existing protected OpenAI connection read-only through the real reader. No direct transports, Unprotect, reflection or another coordinator/worker. Preserve the actual engine's quota, fence, uncertainty and retention behavior.

Never emit prompt/question/answer/result/proposal/ciphertext/token/connection strings. Export only the closed safe evidence DTO and hashes of public fixtures/instructions/schema/profile. A candidate is not a qualified production profile. Do not write production configuration automatically.

Use source AGENTS, the canonical [form rules](../../docs/features/formularios.md), [AI rules](../../docs/features/inteligencia-artificial.md), [configuration guide](../../docs/guides/configurar-ia.md) and [ADR0020](../../docs/decisions/0020-motor-unico-de-ia-con-capacidades.md). Run TDD for harness rules before real calls. Register this folder in the instruction map when promoting these drafts. CLAUDE.md imports this file. Do not reference this harness from product src or the solution.

Audio cases use four committed fictitious Ogg/Wav fixtures (es/en), the same saved OpenAI connection and real IAssistantOperations NormalizeAudio purpose. The isolated host replaces only private file storage with durable local WriteOnce files under its output; it never calls a provider directly or converts a failed Ogg probe automatically. Read-only audio actors have neither Send nor Home. Resume rebuilds the closed channel context from safe ledger identity/scope and calls Get without a new Submit or UUID. It also starts the host and workers: an accepted, still-valid Pending may execute its original provider call. Inspect the private durable state before resuming; terminal or abandoned Running operations are never submitted again. Stop on the first failed mechanical check; keep semantic review pending and never export transcripts or their hashes.

QualificationFormSeed owns fictitious form data only: real authoring/catalog/suggestion/capture services and the real local compiler, with BF publication facts written through Domain factories in the isolated database. In the qualification evidence from 2026-10-18, the local-visit fixture used a real Manual catalog item without English to force the whole original presentation under that cut's rule, while its published questions stayed bilingual. The [current language policy](../../docs/features/formularios.md#idioma-original-y-traducción-opcional--2026-10-19) instead keeps that item's original text/detail without forcing a global fallback; this documentation change neither repeats nor extends the earlier provider qualification. Completed historical sessions reference the actual capture receipt and linked subject; their terminal reviewed offers have no provider receipt, Flow JSON or Meta asset and cannot be dispatched. This fixture qualifies decisions and BF prefill, never Meta publication or delivery.

The isolated Windows host overrides only its DataProtection registration with a per-run private filesystem key ring encrypted with DPAPI. Preserve private-keys alongside the ledger for resume; never copy the app key ring, export keys or silently use plaintext on another OS. Offline checks recreate the host and verify recovery and run separation.

Audio fixture qualification compares the complete canonical token sequence in memory; only punctuation, case and diacritics are ignored. Lost negations, omitted words or translations fail. Export only fixed check IDs and booleans, never transcripts or their hashes.

Home fixture checks bind active/inactive counts to their observed evidence labels and reject negation or reversed public opening hours. Checks remain finite facts, not a claim of exhaustive free-text or human style assessment.

Channel checks validate observed Subject/culture/completeness, exact requested fields and catalog choices, authentic revisions/mappings, the requested clarification pair, filters and whole original presentation. Keep only fixed check IDs and booleans. Assessment must state fixture-facts-checked-in-memory; style/free-text-not-exhaustively-assessed.

Repeated identical Home evidence values are accepted; conflicting counts fail safely. Missing-topic and unsupported catalog-criterion checks bind public fixture concepts (visit/tool loan and eye filtering) in memory; never export their text.

The isolated host loads the Api public base and Development JSON files before user-secrets/environment. Reuse the existing local login-code HMAC and Web client configuration; never copy or print their values or add another OpenAI key. The pure configuration check emits only its fixed ID and boolean. --live --diagnose-existing-fixture reuses the existing run/database under startup-connection READ ONLY plus a read-only transaction. It invokes ListSuggestions and the public IStartupValidator, constructs HomeRunner and hosted service instances without starting them, then reads Bootstrap with a fictitious QualificationHome actor. The real read-only source bridge exposes only enabled/provider/model metadata. No host.Start, seed, ledger, Submit or model call occurs. Diagnostics expose only fixed phases, counts/booleans, exception/option type names and known source basenames/PDB lines; never validation messages or configuration values.

--live --continue-existing is separate from --resume (Get without a new Submit, with the host and workers running) and requires the original full run/binding. Read all existing ledgers through Get before starting the host; never submit an existing accepted or before-submit identity. A before-submit uncertainty or missing original evidence stops safely. Reconstruct actors/forms/captures/offers from the existing evaluation database in a read-only transaction; no migration, seed, source write or quota reset. Preserve initial evidence files and every original timing/metric/profile field; Home fact checks may be reevaluated in memory into reevaluated/. Only cases without any ledger can receive a new UUID and Submit. A local exclusive continuation handle prevents two processes advancing one run. No real continuation until the orchestrator explicitly authorizes effects.

The exact-requested-field-set check stays strict except original-language/local-visit fixtures: one optional branch choice may repeat the explicitly requested place fact only when the unique exact observed choice label equals that public fact. The finite English channel-original-language-en/local-visit case additionally recognizes explicit North branch only as its single exact observed Sucursal Norte choice, with culture en and observed OriginalCulture es; arbitrary translations, other labels/cultures and ambiguity fail. Require place, exact form/version/revision, same turn/ordinal/capabilities/Subject/culture and the exact included form reference in a complete or partial discovery snapshot. Partial discovery never establishes absence; H7 missing requests still require a complete read. Notes, other extras, foreign/ambiguous choices and absent words fail. Keep the check ID; this is a finite facts-backed optional choice, not permission to infer new fields. Continuation may reread the accepted proposal and reevaluate only that check for these two cases, preserving original metrics/profile/other checks/evidence and never resubmitting its UUID.

The preserves-exact-observed-mapping check requires every mapped field unchanged. Only channel-suggestion-es/en may add one notes longText from the same exact observed source alias and the public fictitious notes fact, for the real visit-to-maintenance fixture. Require complete same-turn/capability/ordinal/Subject/culture/source/set and target version/revision evidence; loops, unknown or invented values, wrong types and duplicate fields fail. Other cases keep exact mapped-only lists. Continuation uses Get for the accepted request and reevaluates only this check, preserving initial evidence, profiles, metrics and every other result. No accepted UUID is submitted again.
